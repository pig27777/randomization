## 2026-11-03 · 内容物模型与接触修法复盘（报告和源码审阅，未新增仿真）

依据：`contents/HANDOFF.md`、`contents/newton/unified_soft.py`、`test/gripper_grasp/REPORT.md`、`test/contact_transfer/REPORT_newton170.md` 和 `log/contact_report.md`（已移至 `test/contact_transfer/REPORT_diagnosis.md`）。本条是对已有结果的判断与后续建议，不代表新增测试或平台验收通过。

**内容物模型的问题**：目前还没有一个模型同时满足“可压缩、提起时保持整体性、整体行为能按参数控制”。

- 旧粒子键模型已经写了压实、迟滞和蠕变项，但揉团、枕头受压会塌，标定不收敛。抗拉、抗剪支撑偏弱、缺少可靠体积支撑是候选解释，尚未逐项验证；不能简化成“所有键都不抗拉”。
- 当前均匀四面体海绵是弹性加阻尼的基准，尚未包含目标的压密变硬、卸载残余、迟滞和蠕变。分层生成器的 `skin/core/gap` 都是连接的实体单元，软 `gap` 并不直接表示可闭合、滑动的真实层间空隙；作为等效模型，需要验证整体行为。
- 圆角改善了夹取中的局部压溃，但加密后仍更早翻转，不能把粗网格能夹起当成网格收敛或物理正确。大压缩材料规律和防翻转的求解措施都需要验证，不能断定单加体积屏障即可解决。
- 所有参数仍是设定值，没有实物标定。先验证数值稳定和参数变化的趋势，再讨论对真实内容物的代表性。

**接触诊断的证据与修法边界**：

- 接触权重跳变有逐子步记录支持；固定到形心后，正式节点间手指的支撑误差从 41.9% 降到 0.15%，但压板误差从约 17% 升到 73%，不能作为通用修法。
- “共享接触使每个节点三倍过冲”仍是推测。源码按权重分配力、按权重平方分配刚度，并按颜色依次更新节点；共享接触本身不足以证明该解释。形心补丁还有平行度 0.95 和覆盖范围两个切换条件，应先检查这些切换以及每轮节点更新的穿透、反力。
- 按角点各自穿透拆分接触尚未验证，可能漏掉完全落在节点之间的小工具；强行给工具外的角点施力也会改变接触几何。稳定覆盖区采样或少量多点积分是候选方向，须保留形函数分力、合力/力矩一致性和权重归一化，检查重复接触。
- 源码新疑点：本机 1.7.0 的 `compute_projected_isotropic_friction` 在切向滑移恰好为零时，把切向刚度设为零；而正则化公式在滑移趋近零时有非零极限（摩擦系数和法向载荷为正时）。该不连续可由源码确认；它是否导致膜片的 3–5 mm/s 抖动尚未验证，不能写成已定位的根因。
- 膜片结果已有更新：加摩擦后可随步长减小收敛，但仍有局部抖动；ke 3000 在 0.025 ms 时约 0.013 倍实时。该局部进展没有改变完整平台仍未通过的结论。

**处理顺序**：先对照验证摩擦零速刚度分支、定位形心补丁的压板回归，再选择接触修法；同一实现同时检查节点上手指、节点间手指和压板。接触验收后，以最小四面体模型分别控制压缩、拉伸和剪切，再逐项加入历史效应；同组参数检查压板压缩、小手指局部压入、夹边提起，兼容后再扩展叠平、揉团和枕头，最后装袋。均为待执行建议，本次未改仿真代码、未重跑或新增结果。

## 2026-11-02 · 边/面接触：找到抖动机制

脚本都在 `contents/newton/`，直接调用 `test/contact_transfer/benchmark.py` 的实验和指标，没有修改它；结果在 `results_unified/ef_probe/`、`ef_dedup/`、`ef_centroid/`。设置：1 ms 子步，10 次迭代，接触刚度 3000，接触阻尼 3，无摩擦。“固定”指工具按给定位置不动（`--drive position`），“滑轨”指正式测试的力驱动加竖直滑轨。

**1. 排除的因素**（工具固定、手指在节点之间）：

| 改动 | 最大节点速度 mm/s | 结论 |
|---|---|---|
| 原样 | 812 | — |
| 迭代 40 / 160 | 855 / 860 | 不是迭代没收敛 |
| 接触刚度 300 / 100 | 435 / 471 | 刚度只影响幅度 |
| 接触阻尼 0 / 30 | 661 / 1531 | 不是阻尼 |
| 子步 0.25 ms | 294 | 只减小幅度 |

接触记录数一直是 39 条，不随子步变化；软块底部反力几乎不变（峰峰值 0.001 N）。抖动集中在手指四角外侧的 4 个节点上，每个以 3 个子步为周期上下跳约 ±0.5 mm。

**2. 机制**：逐子步跟踪一个角节点上的接触记录（`ef_normal_probe.py`）。真正受力的是平手指底面下方那条**平放的对角边和两个平放的面**。平的工具压在平的边或面上时，边/面上每一点一样深，“最深点”没有定义；碰撞检测就挑当前稍高的那个端点，把 85–91% 的力压在它身上（该节点在这条记录里的权重在 0.09 和 0.91 之间来回跳）。这个节点被压下去后，下一个子步最深点跳到另一端，如此循环、自我维持。所以它和迭代、刚度、阻尼都无关；手指在节点正上方时，凹坑的最深点稳定在中心节点上，所以干净。

**3. 边/面记录退化成重复的顶点接触**：节点旁有一批边/面记录的权重全落在同一个顶点上，法线和穿透深度都和该顶点自己的记录一样。这次它们没有被激活，不是抖动的原因。去掉权重 ≥ 0.99 的这类记录后，手指在节点之间时界面两侧差从 88% 降到 15%，但抖动还在；压板反而变差（残差 4.6% → 9.8%）。

**4. 验证：把平放的边/面接触点固定在中点/形心**（`ef_centroid_check.py --footprint`，只固定落在工具底面范围内的记录）：

| 场景 | 原样 | 固定到形心 |
|---|---|---|
| 固定工具，节点间手指 | 界面差 88%，残差 108%，812 mm/s | 界面差 0.15%，残差 0.54%，3.8 mm/s |
| 滑轨，节点间手指（正式测试的失败项） | 支撑误差 42%，残差 91%，468 mm/s | **支撑误差 0.15%，工具受力误差 0.49%，残差 1.1%，5.8 mm/s** |
| 固定工具，节点上手指 | 全部通过 | 全部通过 |
| 滑轨，节点上手指 | 残差 2.6%，4.9 mm/s | 残差 2.7%，4.9 mm/s |
| 固定工具，压板 | 界面差 1%，残差 4.6%，35 mm/s | **界面差 75%，残差 88%，415 mm/s** |
| 滑轨，压板 | 支撑误差 17% | **支撑误差 73%** |

手指的问题基本解决，只剩“静止”一项没过（3.8–5.8 mm/s，标准 1 mm/s）；压板反而坏了。不限制范围时，压板边缘处被固定到工具外的点也会出错（节点上手指少传 11.5% 的力），加上范围限制后手指恢复，但压板仍然坏。

**5. 对压板变坏的解释（推测，未单独验证）**：VBD 一次只解一个节点。顶点接触只作用于一个节点，所以解得很准；边/面接触的点被固定到形心后，由 2–3 个节点共享，每个节点单独求解时都想一个人消掉整个穿透（移动约为应有的 3 倍）。压板下有几百条这样共享的硬接触，所以抖动。原样时压板几乎正常，正是因为它的边/面记录大多退化到了顶点上。

结论：Newton 刚体压四面体的问题，根源在全表面接触的边/面接触这条路径：**每条边/面只取一个“最深点”**，工具和边/面平行时这个点会跳；而把它固定住又会变成多个节点共享的硬约束，VBD 逐节点求解处理不好。单纯调参数解决不了。

结论：
1. **矛盾的原因**：我的 95% 在正式测试的工具里能复现（三项都换成我的设置时下陷 6.86 mm，我测的是 7.1 mm），但它只是平均值。节点还在局部抖动，残差 60%，手指也偏离了原位。我那个只看一个瞬间的指标没测出这些。所以我的 95% 作废。

3. **根源在接触本身**：工具固定不动、完全没有工具和软体之间的耦合迭代时，节点间的接触仍然剧烈抖动；节点正上方的接触则完全干净。节点之间只能靠边和面接触，所以**问题在全表面接触的边/面接触这条路径上**（`_eval_soft_ef_contact`），和刚体耦合、滑轨、子步大小都不是主因。
4. 正式报告“Newton 不通过”的结论不变。

## 2026-11-02 · 第 0 步结论修正：Newton 不通过平台验收

另一个会话在 `test/contact_transfer/` 做了更严格的接触传力测试，**以它的 `REPORT.md` 为准**。下一条“第 0 步初步探索”是我做的，结论下得过于乐观，已降级。

它的设置：底层节点固定、关闭重力；压头装在只能竖直移动的滑轨上（无驱动、无阻尼）；载荷 0.2 秒平滑加上；直接加力的对照按压力分布积分分配到节点；节点力由独立的双精度工具计算（有 3 个单元测试）。
验收（最后 0.5 秒的平均）：支撑反力、压头反力、节点力平衡残差都 ≤5%；漂移 ≤0.05 mm，速度 ≤1 mm/s；没有四面体翻转，几何穿透 ≤0.05 mm。

结果：
- **Newton 1.6.1 不通过**。四面体直接受压正确；压板在增加迭代后平均反力正确（误差 0.04%），但一直以约 35 mm/s 振动，残差 5–20%；节点间手指误差 42%，振动 468 mm/s；只用顶点接触时小工具穿过。加阻尼、关 tile、提高 SDF 精度、网格加密、接触系数按面积缩放、改 `k_start`，都没能让所有场景通过。
- **膜片压四面体**（相当于袋子压内容物）：接触刚度 30 N/m、子步 0.1 ms 时 3 次都通过；子步减半或迭代加到 20 都失稳，不算收敛。而且 30 N/m 软到小手指会穿过，这组设置不能用在完整场景里。
- **MuJoCo 3.17**（同一网格、同样的 Neo-Hookean 体积力）：0.1 ms 子步下压板和节点间手指通过，0.2 ms 全部不通过；节点上的手指四面体翻转，膜片失败。GPU 批量版本没有重新验证。
- **网格本身没收敛**：细网格直接受压比粗网格多下陷 5.16%，超过 5%。
- 报告只把问题缩小到“当前接触路径的数值稳定和收敛”，没有定位到具体的求解器缺陷。决定：暂不进入内容物本构扩展和装袋整合。

我的探索和它对照：
- 一致：`k_start` 在 1.6.1 中不起作用；只用顶点接触时小工具会穿过；多加子步或迭代后平均力变准。
- **我的指标漏掉了振动**：我只看 3 秒时一个瞬间的下陷量，没有看节点速度和力平衡残差。我的数据里其实已有迹象（40 次迭代的压板 0.16 m/s，40 子步的节点间手指 18 mm/s）。所以“全表面接触加 20 子步传 80%”只说明平均值，不说明静止。
- **矛盾待查**：节点间手指，我测 95% 且基本静止，它测误差 42% 且剧烈振动。设置差别：我用自由刚体、有重力、底面靠地面接触、2 ms 子步；它用滑轨、无重力、底层固定、1 ms 子步。查清之前，我的 95% 不作证据（I-11）。
- **它没测的**：只用顶点接触的压板。我测到 97%、最后速度 0.05 mm/s，但没查残差，要按它的标准补测（I-09）。
