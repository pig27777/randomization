# 按日期管理测试

公共测试脚本按对象放在 `test/bag_model/`、`test/content_model/`、`test/contact_transfer/` 等主题目录；每轮的记录与新结果按日期组织。日期采用机器运行时的北京时间 `YYYY-MM-DD`，跨日运行归属启动日期，同时记录结束时间。

```text
test/
├── bag_model/                    袋子公共测试、演示、诊断和测速脚本
├── content_model/                内容物测法、测试工具和单元测试
├── contact_transfer/             接触与 Newton 诊断
├── flex3d/                       统一机械臂抓取平台
└── runs/
    └── YYYY-MM-DD/
        ├── README.md             当日索引：对象、问题、版本、报告和结果路径
        ├── bag/<run-id>/          袋子或整包模型的本轮输出
        ├── contents/<run-id>/     内容物模型的本轮输出
        ├── contact/<run-id>/      接触基准输出
        ├── policy/<run-id>/       策略或场景评估输出
        ├── isaaclab/<run-id>/     Isaac Lab 输出
        └── repository/<run-id>/   仓库维护相关的检查记录
```

目录中的对象按测试要回答的问题选择。袋与内容物耦合测试放 `bag/`，在索引中同时注明内容物版本；公共机械臂平台根据被测模型放 `bag/` 或 `contents/`。其余对象直接使用明确的主题名，不放入含义不明的 `other/`。

## 每轮必须记录

在原主题 `REPORT.md` 先写计划，再填结果；当日 `README.md` 只做索引，不复制整份报告。每条记录至少包括：

| 字段 | 要求 |
| --- | --- |
| 运行标识 | 明确的问题与配置，例如 `native-flex-pillow-cpu-r1`，重跑使用新标识 |
| 对象与版本 | 袋子、内容物、接触、策略等；写明模型版本/冻结标签、源码指纹 |
| 问题与标准 | 要回答什么；配置、重复数、通过标准与停止条件 |
| 时间与机器 | 开始/结束时间及 `hostname`，CPU/GPU 与环境版本 |
| 入口与命令 | 仓库根目录可执行的完整命令，输出参数指向本轮目录 |
| 结果 | 通过、失败、受阻、仅入口检查或仅计划，不能混写 |
| 报告与数据 | 指向主题报告的本轮节、配置、关键结果和日志 |

同一轮的 `config`、源码清单、`summary`、日志、轨迹和视频放在同一个运行目录；已有轮次拒绝覆盖。供浏览的精选视频可放 `video/`，同时回链本轮原始数据。

例如，使用已有统一平台启动一个新的内容物短入口：

```sh
.venv/bin/python -B test/flex3d/angles.py --yaw 45 --smoke-seconds .02 \
  --output test/runs/YYYY-MM-DD/contents/flex3d-yaw45-smoke-r1
```

`YYYY-MM-DD` 必须替换为运行日期。短入口只检验入口，不产生物理验收结论；正式运行的计划、锁与验收要求仍遵循 [AGENTS.md](../../AGENTS.md#8-本项目协作约定)。
