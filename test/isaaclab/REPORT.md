## 第 1 轮计划：可行性验证（2026-11-05 开始，2026-11-06 安装启动通过，验证中）

**背景**：用户提出内容物改用 Isaac Lab。Isaac Lab 3.0 的 Newton 后端提供 MuJoCo-Warp（刚体和关节，官方称为主要的、经过验证的路径）、VBD（布料），以及两者的代理耦合（官方 Franka 抓布任务即用此方式）。如果可行，它能同时解决三件事：内容物的 GPU 批量、松装袋（VBD 布料）的批量、以后训练用的框架。但以下几点在文档中没有写明或是实验性的，必须先实测：按环境随机化物理参数、每个环境结构不同、闭环关节、耦合的稳定性。

**分工**：计划由总体判断会话制定；执行由 Isaac Lab 线的负责会话完成（`../../AGENTS.md` 第 8 节）。代码放在 `isaaclab/`，结果放在 `isaaclab/results/`。

**原则（2026-11-05 更新，用户要求用 GPU 训练）**：GPU 训练是主路径，Isaac Lab 是首选的 GPU 平台。本轮先验证可行性，同时为迁移做准备。CPU MuJoCo 上的内容物模型保留为**参考实现**（Isaac Lab 版本要与它对照），CPU 上的小规模训练只作为扩展摘要的初步结果和后备。若 L2–L4 不通过，后备方案是直接在 MJWarp 上实现内容物模型的 GPU 后端。

**期限**：11 月 14 日给出“迁移 / 不迁移”的结论。

**环境**：单独建一个环境（建议 `/home/ubuntu/Dev/Envs/isaaclab`），不动现有的 `mjwarp`、`newton_latest`、`bubble_mailer/.venv`。Isaac Lab 3.0 官方目标为 Isaac Sim 6.2、Python 3.12、PyTorch 2.11（CUDA 13.0）、Warp 1.17、Newton 1.6.1。**安装或下载前，先向用户说明要装什么、从哪里下载、多大，获得同意。** 先确认 Newton 后端能否不依赖完整的 Isaac Sim 运行。

| 编号 | 测试 | 通过标准 |
|---|---|---|
| L1 | 安装与官方示例：运行 `Isaac-Lift-Cloth-Franka`（预设 `newton_mjwarp_vbd_proxy`），分别用 1、64、256 个环境 | 能运行；记录每秒环境步数和显存 |
| L2 | 分段内容物在 MuJoCo-Warp 路径上：用 `contents/segment/` 的描述层生成三类锚点（只读调用），写 Isaac Lab 适配层：每段一个刚体，段间用 D6 关节（驱动刚度和阻尼表示弹簧，限位表示锁死） | 能构建；闭环关节网格能求解，或给出可行的替代（生成树 + 等式约束等）；静置和 R1–R3 不发散 |
| L3 | 与 CPU 参考对照：三类锚点的 R1、R2、R3 | 与 CPU MuJoCo 版本（`contents/segment/` 当前冻结或候选版本）相差 ≤ 10%；差得多时说明原因（例如压密 weld、连接力的实现差异） |

| L5 | 松装袋（VBD 布料）+ 内容物 | 用 `bag_sim` 的牛皮纸袋网格做布料，装入硬盒，按 `../policy/README.md`（v2）做侧夹和顶面抓各 3 次：不发散，内容物不穿出，能出现袋内滑动；记录速度 |
| L6 | 吞吐 | 软物锚点 + 平行夹爪的抓取流程，256 和 1024 个环境下每秒完成的抓取次数；有布料和无布料分别报告 |

**结论规则**（11 月 14 日）：

| 结果 | 决定 |
|---|---|
| L1–L4 通过，L6 明显快于 CPU（≥ 10 倍） | 迁移：进入第 2 轮，把任务协议 v2 的完整 evaluate 搬到 Isaac Lab，作为 GPU 训练环境；L5 通过则松装袋也迁移 |
| L2/L3 通过但 L4 不通过（不能按环境随机化） | 不迁移训练；可用于固定参数的批量评估 |
| L2 或 L3 不通过 | 不用 Isaac Lab 训练内容物；改走后备方案：直接在 MJWarp 上实现内容物的 GPU 后端；记录阻碍点 |
| 只有 L5 通过 | 只把松装袋放到 Isaac Lab，评估耦合方案的工作量 |

**本轮不做**：修改 `contents/segment/` 或 `bag_sim/` 的代码；策略训练；真机。

- **L4**：同结构 64 环境，3 批（种子 20261105/20261106/20261107）；质量、刚度、阻尼、限位、摩擦逐项改变并读回，同时做相应受力/自由衰减/越限/滑动响应检查。不同结构用三类锚点段数混合做 3 批构建与运行，失败时实测按段数分桶。配置值、读回值和动力学响应分别报告。
- **L5**：只读使用原始 `kraft.npz` 与 `profiles/kraft.json`；装入满足 v2 侧夹尺寸限制的小硬盒，侧夹和顶面抓各 3 次（种子同上），记录有效结果、sim_fail、穿出证据、袋内相对滑动及速度。袋初态、盒子尺寸/质量、抓取位置/力等具体配置在首次动力学运行前补齐，不用历史结果代替本轮。
- **L6**：三类锚点 + v2 平行夹爪，有布料/无布料 × 256/1024 环境，各配置 3 批完整抓取；先做单环境入口检查。CPU/GPU 使用相同可执行物体、动作、流程、提前终止及计数方法，记录总尝试、有效完成、sim_fail、耗时与抓取/秒，再比较原 ≥10 倍线。不能用 L1 步速或历史 CPU 提前失败的耗时推算完整抓取吞吐。

**L2 替代路径配置（2026-11-06 13:38，运行前补充）**：原生软物闭环 D6 被转换器跳过后，测试每条闭环增加无碰撞代理刚体（质量 1e-9 kg、对角惯量 1e-12 kg·m²），原 D6 连接至代理，代理与真实子段以 WELD 等式闭环。等式 `solref=(0.001,2)`、`solimp=(0.95,0.99,0.0005,0.5,2)`；记录额外质量和每条等式，不把代理或额外质量隐去。三类各一次构建入口，成功后静置 0.3 s（0.4 ms，750 步），只作替代入口，后续仍须原定三次 R1–R3 与 ≤10% 标准，不因构建成功放行 L2/L3。

**L2 替代入口修复（13:50）**：第一次运行默认约束缓冲溢出，改 `njmax=nconmax=4096`。随后发现 Newton 自动把 1e-12 代理惯量抬到约 1.0001e-6，原微小惯量假设未成立；易压物在 t=0.0924 s 非有限。保留这批失败，不据此判整个替代方法无解。下一次将代理质量/惯量明确设为 1e-5 kg/1e-9 kg·m²，以避开已读回的自动修正并减轻质量比；易弯/易压额外质量分别 0.37/0.57 g（0.128%/0.114%），仍按原 CPU/GPU ≤10% 线判断，不变更标准。
